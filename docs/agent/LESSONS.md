# Lessons

使用者糾正轉成可執行規則，最新放最上方。新條目記錄「來源／遇到 X，應做 Y／如何驗證」；不要把 agent 的推測寫成使用者要求。同一錯誤重犯時重寫原條目，已過時的規則註明取代來源再移除。

## 2026-10-16

- 遇到團圓金色與黃色圖片混用，以使用者最新實物附件的淺香檳米金織紋辨認金色；不能因舊圖檔名或選項標籤就沿用亮黃布面。只調指定底色，對照松針印刷、金魚與品牌刺繡、盒型、拉片和展示尺度；以原圖、附件及生成圖並排和局部放大驗證。（來源：使用者附件2YwKef與「這個顏色是金色，印刷跟刺繡都一樣」指示。）

- 遇到三盒可混搭的商品，不能讓 Shopify adapter 一律清除 mixBoxes，也不能只換選單而讓 cart 丟失混搭明細。以實際 variant GID 記錄各茶盒數，伺服器驗證總數3盒、整組US$60並走共用預購SKU；商品摘要的每盒包數要由整組6包換算為2包。驗證不同／重複口味、未選齊、購物車重載、兩組價錢與後台明細。（來源：使用者指出聖誕心意禮目前只能選一款、要求可混搭。）
- 遇到客戶已在 Shopify 改顏色／選項且指定原商品不用動，應先讀取現行 variant GID、名稱與售價，再補對應的預購 selling plan；不得沿用舊 Gold-only 篩選、把新色當舊色照片或重設共用預購額度。以三色下拉、購物車 plan／Option 與前後庫存比對驗證。（來源：客戶今日金色／黃色／紅色及選單統一截圖。）

## 2026-10-15

- 遇到商品細節被指出模糊，必須分開檢查實拍對焦、主體實際像素與網頁縮放，不能以「原商品 RGB 未改」或輸出畫布尺寸當作高清證明。要求重生時以實物鎖定盒型／圖案／字樣／數量，讓生成畫面有足夠主體像素，再正規化展示比例；放大核對盒底、雪花與 Logo，不用柔化邊緣掩蓋缺陷。（來源：使用者指出盒底模糊並要求重生高清；從本機 WIP 合併保留。）
- 當商品陰影被指出不自然時，按指定參考分析接地位置、面積、方向與濃淡，不用單一橫長橢圓／水平灰線代替真實投影。背景漸層同時檢查原檔與網頁解碼的色帶、階梯及縮放紋理；以足夠精度及微量去色帶處理，商品本體不可一起模糊。以 200% 背景局部、盒底投影與相鄰視角並排驗收。（來源：使用者指定圖二陰影，並指出整系列背景鋸齒；從本機 WIP 合併保留。）
- 當新增實拍商品照時，先完成一致背景與主體尺度，再接圖庫；不可將完整照片套 contain + padding:20%，造成照片框在照片裡及二次縮小。開盒照以盒身寬度對齊既有正面／斜角，盒蓋增加高度不代表縮小整個盒子；維持 4:5 棚拍畫布及既有 cover 呈現，驗證背景接縫、盒身比例及實際頁面。（來源：使用者要求根據目前邏輯修改，商品大小比例一致；從本機 WIP 合併保留。）

- 使用者要求「拉開每一個步驟的間距」時，應比較實際每列高度與整段圖文比例，不只小幅增加 padding；桌機/手機驗證五個節點連線、分隔線及最後一步的留白。來源：本輪使用者指出前次留白仍不夠；使用者其後更正為第五步與圖片底部對齊，應移除 guide 尾端空白並依圖片/末節點實際位置設定動畫終點，桌機驗證底緣差不超過 1px。

- 當使用者提供同時含「串接前預購上限」及「串接後可售合計」的表格，分開保存兩種語意；整款合計不可重複寫到每個variant。使用者已明確指定聖誕心意禮三盒一組、共200組，取代舊單盒規則；單位變更不代表可自行推算售價；使用者其後明確確認每組US$60，依此完成轉換。驗證逐variant加總、null發布狀態與商品販售單位。（來源：2026-10-15庫存表及兩次回覆。）

- 遇到配送範圍或履約庫存與舊截圖衝突，套用最新明確指示：SGV 僅現場銷售、不寄貨，所有網購使用 Hayward 庫存；不寄 Alaska／Hawaii（取代早先可寄、另計運費）。驗證不能只看頁面文案，要核對 Shopify online fulfillment、location group／zone 與實際可售數量。（來源：使用者本輪兩次配送回覆，2026-10-15。）
- 當用瀏覽器量 sticky／ScrollTrigger 的釘住位置時，先關掉電子報視窗（點 `[aria-label="關閉電子報視窗"]` 或設 `localStorage` `cv-newsletter-popup-seen=1`）：它把 `html/body` 設成 `overflow: hidden`，sticky 會失效、數字看起來像「沒釘住」而其實是量錯。驗證：`getComputedStyle(document.body).overflow` 不是 `hidden` 再量 figure top。（來源：本輪 agent 量測沖泡區時的誤判，非使用者指示。）
- 當驗收捲動動畫時，截圖要標實際的進度變數值（例如 `--brew-stage`），不能只信檔名；「01-pour」可能是步驟 1 結束的畫面。起點要在軸線 start（stage 0）確認「第一個動作發生時主體在畫面內」（這次：壺倒水時杯身要在摺線上），桌機 1440×900 與 1800×1125 都量。（來源：本輪 Ego Lite 檢視發現 74% 起點讓水位在畫面外上升。）
- 當用 Ego Lite Browser 做視覺檢視時，不可只靠視窗或截圖檔名推測 viewport；每輪設定 CDP `Emulation.setDeviceMetricsOverride` 後回讀 `innerWidth/innerHeight` 並 assert。2026-10-15 柔影／背景與底部對齊 QA 已驗證 1440×900、390×844，取代先前固定 1800×1125 的局部觀察；截圖沿用已確認有效的 `Page.captureScreenshot`。（來源：本輪實際 viewport 及截圖證據，非使用者指示。）

## 2026-10-14

- 遇到「原圖清楚、桌機商品圖模糊」，先比對 currentSrc、實際解碼像素、DPR 與 object-fit 的縮放；高容器使用 cover 時，尺寸需求可能由高度決定，不能只用欄寬寫 sizes。原圖已是適當大小的壓縮 WebP 時，可讓桌機主圖直接用原圖、手機與縮圖保留最佳化；同時驗證沒有重複 preload，避免重畫商品或只提高 quality 掩蓋尺寸不足。

- 當既有雙語網站接入Shopify時，先盤點已核准中文並遷入Shopify翻譯／CMS欄位；不能因Shopify尚無翻譯就讓中文頁退回英文，也不能把本來有的文案列成待使用者補齊。價格和庫存仍以Shopify為準。

- 當使用者指定「Visual 照片、Shopify 商品資料」兩個來源時，分別維護影像與商品身分對照；價格、庫存、規格依 Shopify，照片依已核准 Visual。用 variant 身分配圖，不用陣列順序，也不把舊前台預購額度反寫商店。

## 2026-10-13

- 當交付商品圖或公開圖說時，不自動加入「AI-generated／AI 生成」、模型名稱或製程水印；使用內容本身的描述與 alt text，製程資訊只留內部記錄。檢查圖面、caption、alt 與周邊文字；不得把生成的人物或情境當成真實員工或事實證據。（來源：使用者提供的 AGENTS.md「Public image text preference」，2026-10-13。）

- 當做新禮盒的商品圖時，一開始就拿網站同一視角的現有商品圖（例如 `listing-tea-spring-dawn-*-even2`、`studio-*-end-angle-even2`、`gift-box-unboxed-12-v2-even2`）當構圖＋光影＋影子參考，提示詞寫明「明亮高調、大面積柔光、淺暖灰底無暗角、影子淡而往右下漸淡、盒底無黑邊」；不要自己寫「靠盒底最深」這類硬影子。正規化一律用 `norm.py` 的 0.45（網站現行值），交付前和網站同類圖並排比大小、影子與底色（使用者：「影子都處理得很醜！！！不要再犯」）。
- 當用客戶近拍的實拍照（正面、開箱）做圖庫時，先檢查鏡頭變形（外盒變梯形、看不到側面）；要透視校正成長方形再去背，否則外盒會像一張紙板（使用者：「盒子外盒也有問題」）。
- 當要填客戶還沒給的價格時，不要自己推算數字放上網站；用「價格待訂／Price to be announced」並停用購物按鈕（使用者：「US$130 幫我用價格代訂，不要自己亂寫」）。其他推理的暫定事實要在資料旁註明待客戶確認。
